# HoloNight Viewer 0.1.0 — First source release

The first source release of HoloNight Viewer is a keyboard-first static-image
viewer for **native Wayland**. Build it from source with separately installed
HoloNight providers. No distribution packages, portable binaries or bundled
providers are supplied. X11 and XWayland are outside the supported scope.

## Features and formats

- Open one local image by command-line path, file drop or Open; asynchronous
  decoding honors embedded orientation and keeps errors recoverable.
- Fit, physical-pixel actual size, pointer-centered zoom, mouse/keyboard pan,
  fullscreen, natural-order folder browsing and refresh with bounded caching.
- Temporary rotate/flip, image information, shortcut help, image/path copy,
  themed controls, visible keyboard focus and accessibility announcements.
- Guaranteed static formats: **PNG, JPEG, BMP and WebP**. Other Qt image handlers
  are best effort; animated files show their first frame only. Originals remain
  unchanged. Install Qt Base PNG/BMP/JPEG and Qt Image Formats WebP support.

Viewing limits are 256 MiB encoded input, 32 million pixels, 32,768 pixels per axis
and 128 MiB per decoded image. Retained display plus cache is bounded at 256 MiB;
decoding, rendering, clipboard encoding and platform transport add temporary
memory. Clipboard persistence after exit belongs to the desktop.

## Build and installation

Requires a C++23 compiler, Qt **6.11+** (Core, Gui, Quick, Qml, QuickControls2),
CMake 3.25+, Ninja, Task, tomlplusplus, pkg-config and libwebp. Tests additionally
need Qt Test, GTest and Python 3. Contributor checks require clang-format,
clang-tidy/run-clang-tidy, REUSE, desktop-file-utils and GIO. The
[CI Dockerfile](https://github.com/lebedenko/holonight-viewer/blob/v0.1.0/packaging/Dockerfile.ci)
records the Arch packages.

Exact tested provider revisions:

| Separately installed provider | Revision |
| --- | --- |
| [holonight-config](https://github.com/lebedenko/holonight-config) | `fe69a59e6b73167fd5349223a4d265d75386c139` |
| [holonight-qt](https://github.com/lebedenko/holonight-qt) | `22ded7815727ce483fd91e82a9cc04bfe252ec3b` |

Native qualification used Qt 6.11.2. Build both providers against the **same Qt
build as Viewer**: provider private Qt API use ties runtime ABI to that Qt build.
Install Config first, then Qt, following their build instructions, with a shared
installation prefix. Viewer consumes installed HolonightQt::Core/Controls and QML
modules; its source archive does not include providers. Rebuild providers when
changing the Qt build.

After verifying and extracting the attached archive, configure against an existing
provider installation (replace `/path/to/installed/providers` with its absolute
prefix; adapt `lib` to the platform):

```sh
sha256sum -c SHA256SUMS
tar -xzf holonight-viewer-0.1.0.tar.gz
cd holonight-viewer-0.1.0
provider_prefix=/path/to/installed/providers
export QML_IMPORT_PATH="$provider_prefix/lib/qt6/qml"
export LD_LIBRARY_PATH="$provider_prefix/lib"
task build PRESET=release HOLONIGHT_DEPENDENCY_PREFIX="$provider_prefix"
task test HOLONIGHT_DEPENDENCY_PREFIX="$provider_prefix"
task install-check HOLONIGHT_DEPENDENCY_PREFIX="$provider_prefix"
# Stage for inspection without modifying the host:
DESTDIR="$PWD/build/stage" cmake --install build/release
QT_QPA_PLATFORM=offscreen build/stage/usr/bin/holonight-viewer --version
# Install to /usr when ready:
sudo cmake --install build/release
sudo update-desktop-database /usr/share/applications
holonight-viewer -- '/path/to/photo.png'
```

Direct CMake builds can configure with `cmake --preset release
-DHOLONIGHT_DEPENDENCY_PREFIX=/path/to/installed/providers
-DHOLONIGHT_QML_IMPORT_PATH=/path/to/installed/providers/lib/qt6/qml`, followed by
`cmake --build --preset release`. For system providers use `/usr` and
`/usr/lib/qt6/qml`; normal Qt paths then discover installed modules. A custom
provider prefix needs the QML/library environment above at runtime. Set
`CMAKE_INSTALL_PREFIX` at configure time for a custom Viewer installation and
expose its bin/share through PATH/XDG_DATA_DIRS. The install includes executable,
desktop entry, icon and GPL licenses; it does not change the default image app.
Remove a previous development desktop registration if it shadows the system entry
(see README).

## Accepted qualification and performance

The user accepted the measured tradeoffs on 2026-09-10. Five native trials used
8000×4000 alpha fixtures, Qt 6.11.2, labwc 0.20.2/wlroots 0.20.2, OpenGL, a
1000×700 logical window at scale 1.5 and an Intel i9-9900K. All five candidate
clipboard receptions preserved expected dimensions, color and alpha without hangs
or crashes. Candidate medians: updated-frame open **163 ms**, navigation **216 ms**,
eight rendered transforms **127 ms**, copy preparation/publication **967 ms**, and
copy initiation through receiver completion **1359 ms** (range 1333–1372 ms).
Separate process peak RSS medians were **692.5 MiB Viewer** and **496.9 MiB receiver**;
maximum observed GUI timer gaps ranged 63–105 ms.

These machine/fixture-specific results are not universal latency or memory bounds.
Qt frame completion is not physical display latency; copy includes receiver startup
and compositor activation. RSS includes validation work and cannot be added into
a simultaneous combined peak. The faster historical baseline lost alpha in all
five trials, so its timings are not equivalent successful transfers. Full methods,
trials, earlier native acceptance and limitations remain in the
[qualification record](https://github.com/lebedenko/holonight-viewer/blob/v0.1.0/docs/sdd/release-readiness/VERIFICATION.md).

## Explicit next-release deferrals

These remain unresolved and were explicitly deferred from this release:

1. **Native Open/provider-dialog acceptance:** the default HoloNight theme lacks
   native-dialog delegation. A per-process `QT_QPA_PLATFORMTHEME=xdgdesktopportal`
   comparison passed selection/cancellation; default-provider acceptance remains
   open. See the [provider handoff](https://github.com/lebedenko/holonight-viewer/blob/v0.1.0/docs/holonight-qt-dlg-delegation-missed.md).
2. **Physical mixed-monitor/mixed-scale movement:** no second physical monitor was
   available; movement/rendering/focus/dialog behavior is not accepted by simulated
   scale checks.
3. **Clipboard persistence-service behavior and costs:** persistence after exit,
   manager memory and transport costs remain unqualified; no persistence service
   ran in the native performance measurements.
